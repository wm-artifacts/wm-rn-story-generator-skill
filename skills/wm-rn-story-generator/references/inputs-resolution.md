# Inputs Resolution (Phase 1)

Goal: take the caller-supplied runtime component path (and optional existing story directory) and derive every value the rest of the workflow needs.

In this repo, stories generated by this skill live under `storybook/stories/wm-{category}/wm-{slug}/{slug}.stories.tsx`. The component is imported directly from the runtime package.

---

## 1.1 Required Input

The caller must provide a component source path. Paths are classified into two tiers:

### Primary paths (WM runtime — import auto-derived)

- `basic/anchor` — short form: `{cat}/{slug}`
- `input/text`
- `@wavemaker/app-rn-runtime/components/advanced/carousel` — full package form

Strip the `@wavemaker/app-rn-runtime/components/` prefix if present, then split on `/`. The last segment is the slug; the second-to-last is the category. `componentImportPath` and `componentExportName` are auto-derived (see § 1.2).

### Secondary paths (any other source — import caller-supplied)

- Other npm package: `@my-org/components/input/button`
- Relative path: `../../packages/my-lib/components/basic/button`
- Direct node_modules: `node_modules/my-lib/components/basic/button`

For any of these, split on `/`. The last non-empty segment is the slug; the second-to-last is the category. `componentSourceDir` is resolved from the path (see Path Classification below). `componentImportPath` **must be supplied by the caller** — see § 1.1a.

### Path Classification (detection order — apply first match)

1. **WM short** — no `@`, no `..`, no `./`, no `node_modules/` prefix, and at most two `/`-separated segments. → `componentSourceDir = node_modules/@wavemaker/app-rn-runtime/components/{cat}/{slug}`
2. **WM full** — starts with `@wavemaker/app-rn-runtime/components/`. Strip prefix, then same as WM short.
3. **Other npm package** — starts with `@` (but not `@wavemaker/app-rn-runtime`). → `componentSourceDir = node_modules/{path}`
4. **Arbitrary path** — starts with `..`, `./`, `/`, or `node_modules/`. → `componentSourceDir = {path}` (resolved from repo root).

If the classified `componentSourceDir` does not exist, see [stop-conditions.md](stop-conditions.md).

---

## 1.1a Secondary Path — Import Path Requirement

When the path classifies as **secondary** (tiers 3 or 4 above), the story's `import` statement cannot be auto-derived. The caller **must** supply `componentImportPath` explicitly (e.g. as a second argument alongside the source path).

If `componentImportPath` is not supplied for a secondary path, **stop and ask** before proceeding to Phase 2. Surface: the source path, the resolved `componentSourceDir`, and what import path is needed.

`componentExportName` for secondary sources is read from the default export in `{componentSlug}.component.{tsx|ts|js}` (see § 1.2). If no default export can be resolved and the caller has not supplied the export name, **stop and ask**.

---

### Optional second input — update flow

The caller may also supply an existing story directory, e.g. `components/WmAnchor`. When supplied, this triggers the **update flow** (§ 1.4).

## 1.2 Derived Values

| Derived value | Rule | Example |
|---|---|---|
| `componentSlug` | Last path segment, lowercased | `anchor` |
| `componentName` | `Wm` + PascalCase(slug) | `WmAnchor` |
| `sourceCategory` | Second-to-last path segment | `basic` |
| `storyCategoryGroup` | `wm-{sourceCategory}` | `wm-basic` |
| `storyCategoryTitle` | Mapping below | `Basic` |
| `componentExportName` | Primary: `Wm` + PascalCase(slug). Secondary: read default export name from `{slug}.component.{tsx\|ts\|js}`; stop and ask if unresolvable | `WmAnchor` |
| `componentImportPath` | Primary: auto-derived as `@wavemaker/app-rn-runtime/components/{sourceCategory}/{componentSlug}/{componentSlug}.component`. Secondary: **caller-supplied** (§ 1.1a) | `@wavemaker/app-rn-runtime/components/basic/anchor/anchor.component` |
| `componentSourceDir` | From Path Classification (§ 1.1) — primary: `node_modules/@wavemaker/app-rn-runtime/components/{sourceCategory}/{componentSlug}`; secondary: resolved from caller-supplied path | `node_modules/@wavemaker/app-rn-runtime/components/basic/anchor` |
| `storyDir` | `storybook/stories/{storyCategoryGroup}/wm-{componentSlug}` | `storybook/stories/wm-basic/wm-anchor` |
| `storyFile` | `{storyDir}/{componentSlug}.stories.tsx` | `storybook/stories/wm-basic/wm-anchor/anchor.stories.tsx` |
| `docsDir` | `{storyDir}/docs` | `storybook/stories/wm-basic/wm-anchor/docs` |
| `metaTitle` | `{storyCategoryTitle}/{Pascal(componentSlug)}` | `Basic/Anchor` |
| `relativePathToStorybook` | from `storyDir` back to repo root | `../../../../` |
| `relativePathToConstants` | from `storyDir` to `constants/constant` | `../../../../constants/constant` |
| `relativePathToServices` | from `storyDir` to `services/` | `../../../../services/` |
| `relativePathToComponentDocumentation` | from `storyDir` to `.storybook/components/ComponentDocumentation` | `../../../../.storybook/components/ComponentDocumentation` |

> **PascalCase rule**: hyphenated slug `bottom-sheet` → `BottomSheet` → `WmBottomSheet`. The `metaTitle` segment is the un-prefixed PascalCase (e.g. `Basic/Anchor`, not `Basic/WmAnchor`) to match existing stories.

### Category → title mapping

| `sourceCategory` | `storyCategoryTitle` |
|---|---|
| `input` | `Form` |
| `basic` | `Form` if the component is a form element (e.g. `button`); otherwise `Basic` |
| `container` | `Containers` |
| `advanced` | `Advanced` |
| `chart` | `Charts` |
| `data` | `Data` |
| `dialogs` | `Dialogs` |
| `navigation` | `Navigation` |
| `page` | `Layout` |

If `sourceCategory` doesn't match any row, see [stop-conditions.md](stop-conditions.md).

### Disambiguation rule

When the mapping is ambiguous (especially `basic` between `Form/...` and `Basic/...`), search existing stories first:

```bash
grep -r "title:" components storybook --include="*.stories.tsx" | grep -i "{ComponentName}"
```

Mirror the prefix of any sibling story for a similar component. If no precedent and confidence is low, stop and ask.

## 1.3 `.storybook/main.ts` glob append

On first run, the new `storyDir` won't be discovered by Storybook. Idempotently append to the `stories` array in `.storybook/main.ts`:

```js
"../storybook/stories/**/*.stories.@(js|jsx|ts|tsx)"
```

If the entry is already present, skip — never duplicate. Surface the edit (or "already present, skipped") in chat.

---

## 1.4 Update flow (when existing story directory is supplied)

When the caller supplies `existingStoryDir` (e.g. `components/WmAnchor`):

1. **Read** `{existingStoryDir}/{componentName}.stories.tsx`.
2. **Catalogue every `export const X: Story = …`:**
   - `Basic` → folds into the new `Standard`.
   - `Showcase` → folds into the new `Showcase`.
   - Other named exports (`WithIcon`, `WithBadge`, …) → re-emitted in the new file as **carry-over variants**.
3. **Prop-diff audit** — print before any file is written (hard checkpoint):

   ```
   Carry-over: WithIcon
     keep:    caption, iconclass, hyperlink, classname, onTap
     strip:   <props no longer in {slug}.props.js>
     add:     <new required props from Phase 2 with safe default>
   ```

4. **Preserve callback wiring verbatim** (e.g. `onTap: action("onTap")` stays exactly as written).
5. **Read `{existingStoryDir}/docs/*.md`** if present. Port prose into the new `overview.md` / `styling.md` / `token.md` stubs. (The three auto-generated files always regenerate from source.)
6. **Legacy file is never modified or deleted** — leave `{existingStoryDir}/` untouched.

---

## 1.5 Story location

Stories generated by this skill always live at `storybook/stories/wm-{sourceCategory}/wm-{componentSlug}/{componentSlug}.stories.tsx`. Do **not** detect or guess.

If `{storyFile}` already exists and the user did not say "regenerate" or "update", see [stop-conditions.md](stop-conditions.md).
